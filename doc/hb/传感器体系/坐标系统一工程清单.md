# **坐标系统一（TF）工程清单**

---

## **一、明确机器人坐标体系**

通常室内清洁机器人可定义如下常用坐标系：

| 坐标系           | 描述       | 典型位置 / 作用     |
| ------------- | -------- | ------------- |
| `base_link`   | 机器人本体参考系 | 机器人质心或车轮中心    |
| `odom`        | 里程计参考系   | 用于短期定位，跟随运动漂移 |
| `map`         | 全局地图参考系  | SLAM 输出的全局坐标系 |
| `laser_link`  | 激光雷达     | 雷达安装位置与方向     |
| `imu_link`    | IMU      | IMU 安装位置与方向   |
| `camera_link` | 摄像头      | 摄像头光学中心       |
| `footprint`   | 导航成本地图参考 | 机器人底盘投影       |

> 核心原则：**所有传感器数据在发布时都应对应其坐标系，并通过 TF 正确映射到 `base_link`。**

---

## **二、TF 发布清单**

1. **静态 TF（Static Transform）**

    * 机器人固定结构之间的坐标变换
    * 示例：`base_link → laser_link`、`base_link → imu_link`、`base_link → camera_link`
    * 工程建议使用 `static_transform_publisher` 或 URDF 固定节点

2. **动态 TF（Odometry / SLAM 输出）**

    * `odom → base_link` 由里程计/轮式编码器更新
    * `map → odom` 由 SLAM /定位模块输出，用于全局修正

3. **TF 核心原则**

    * **树形结构**：`map → odom → base_link → sensors`
    * **保证唯一父节点**：每个 TF 有且只有一个父节点
    * **TF 时间戳同步**：与时间同步工程配合，避免位姿跳变

---

## **三、TF 检查与验证**

1. **工具检查**

    * `ros2 run tf2_tools view_frames` → 生成 TF 树图
    * `ros2 run tf2_tools echo /tf` → 检查实时发布内容
2. **坐标一致性测试**

    * 激光雷达点云与地图对齐
    * IMU 姿态旋转与 base_link 方向一致
    * 摄像头标定板测试，验证摄像头坐标系

---

## **四、常见工程问题与处理**

| 问题        | 原因                                | 处理方法                              |
| --------- | --------------------------------- | --------------------------------- |
| 地图与机器人不对齐 | `map → odom` TF 未更新或时间不同步         | 检查 SLAM 输出 TF、时间戳一致性              |
| 激光扫描偏移    | `base_link → laser_link` 静态 TF 错误 | 使用实际安装测量值更新 TF                    |
| IMU 姿态错误  | `imu_link → base_link` 坐标系未旋转匹配   | 调整 IMU 安装角度或旋转矩阵                  |
| 摄像头与雷达不对齐 | 坐标系原点或方向未统一                       | 测量安装参数，修改 URDF / static_transform |

---

## **五、TF 工程实践顺序**

1. **机器人机械参数测量**

    * 激光、IMU、摄像头、轮式编码器安装位置、方向
2. **静态 TF 发布**

    * 固定坐标变换全部发布
3. **动态 TF 接入**

    * 里程计 / SLAM 输出 TF 与静态 TF 链接
4. **时间同步验证**

    * 确保 TF 时间戳与传感器时间同步
5. **可视化与验证**

    * rviz / tf2_tools 检查 TF 树与点云对齐
6. **异常处理**

    * TF 跳变、数据延迟、丢帧处理机制
