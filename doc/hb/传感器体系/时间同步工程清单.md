# **时间同步（时间戳）工程清单**

## **一、确定系统时间基准**

1. **选定统一时间源**

    * 系统时钟（ROS2 Time / Linux Clock）
    * MCU / SoC 硬件时钟（机器人运动控制器）
2. **统一所有传感器时间基准**

    * 激光雷达、IMU、里程计、摄像头
    * 所有数据应映射到同一时间基准

---

## **二、传感器时间戳采集**

| 传感器  | 时间戳来源                   | 注意事项                 |
| ---- | ----------------------- | -------------------- |
| 激光雷达 | 硬件生成或驱动提供               | 检查消息头时间戳单位（秒 / 纳秒）   |
| IMU  | MCU / 内置时间戳             | 高速 IMU 时需注意溢出或漂移     |
| 里程计  | MCU 或驱动                 | 必须与激光雷达保持一致参考系       |
| 摄像头  | 硬件触发 / V4L2 / ROS2 相机驱动 | 若多摄像头需同步触发（外触发或 PTP） |

---

## **三、数据时间对齐**

1. **ROS2 内部时间同步**

    * 使用 `message_filters::TimeSynchronizer` 或 ApproximateTime
    * 对激光 + 里程计 + IMU 做消息对齐
2. **延迟补偿**

    * 传感器采集 → 处理 → 发布存在延迟
    * 记录延迟并在 SLAM /定位节点中补偿
3. **插值策略**

    * 当频率不一致时，对里程计 / IMU / 激光进行线性插值

---

## **四、硬件级同步（可选）**

1. **MCU / SoC 输出统一触发信号**

    * 给摄像头和 IMU 统一硬件触发
2. **激光雷达同步**

    * 外部触发或 PTP（Precision Time Protocol）同步
3. **高精度 IMU**

    * 支持 PPS（Pulse Per Second）信号同步

---

## **五、软件层面处理**

1. **时间漂移检测**

    * 定期检测激光雷达 / IMU / MCU 的时间漂移
    * 若漂移超过阈值 → 自动校正
2. **消息缓存**

    * 在 SLAM 节点建立缓存队列，按时间戳排序
    * 保证 scan / odom / imu 对齐
3. **异常处理**

    * 丢帧、重复帧 → 丢弃或补插值
    * 时间戳跳变 → 丢弃数据或重新同步

---

## **六、SLAM / 导航调优要点**

1. **Scan matching**

    * 确保激光扫描与里程计在同一时间
2. **IMU 融合**

    * 时间戳不准会导致姿态漂移、地图抖动
3. **里程计补偿**

    * 低频里程计数据需插值对齐激光
4. **回环检测**

    * 对时间敏感，时间错位会导致回环失败
