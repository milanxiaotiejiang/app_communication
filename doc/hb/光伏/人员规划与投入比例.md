# 人员规划与投入比例

## 一、人员配置原则

本项目属于**“移动机器人 + ROS 2 系统 + 光伏场景算法”**的综合型工程，人员配置遵循以下原则：

* **核心算法 + 系统为主，机械与硬件为辅**
* **前期重算法与架构，后期重工程化与稳定性**
* **阶段性投入，避免一次性全员铺开**
* **关键岗位具备“可复用能力”，减少人力冗余**

整体以 **8–12 人规模** 为宜，可根据企业资源进行裁剪。

---

## 二、岗位角色划分

### 1️⃣ 项目管理与系统设计层

| 角色            | 人数 | 核心职责               |
| ------------- | -- | ------------------ |
| 项目负责人 / 技术负责人 | 1  | 总体技术路线、系统架构、关键方案决策 |
| 项目经理（可兼职）     | 1  | 进度推进、跨组协调、里程碑管理    |

> 该层决定项目是否“走弯路”。

---

### 2️⃣ 机器人系统与 ROS 2 平台层

| 角色            | 人数 | 核心职责                                    |
| ------------- | -- | --------------------------------------- |
| ROS 2 系统工程师   | 2  | Package 分层、节点架构、通信机制                    |
| 中间件 / 系统集成工程师 | 1  | Nav2、slam_toolbox、robot_localization 集成 |

主要负责：

* ROS 2 架构设计
* 多传感器接入
* 生命周期节点
* 状态机 / 行为树
* 日志、调试、部署

---

### 3️⃣ 定位与感知算法层（核心）

| 角色      | 人数  | 核心职责              |
| ------- | --- | ----------------- |
| 定位算法工程师 | 2   | 局部 SLAM、里程计融合、重定位 |
| 感知算法工程师 | 1–2 | 通道识别、板边检测、中心线估计   |

重点投入方向：

* 局部 SLAM（无图连续位姿估计）
* GNSS / RTK + IMU + Odom 融合
* 光伏通道几何约束建模
* 作业面感知鲁棒性

这是项目的**技术护城河**。

---

### 4️⃣ 控制与底盘层

| 角色      | 人数 | 核心职责            |
| ------- | -- | --------------- |
| 运动控制工程师 | 1  | 底盘控制、路径跟踪、速度规划  |
| 嵌入式工程师  | 1  | 电机驱动、传感器采集、通信协议 |

主要负责：

* 低速 AGV 控制
* 通道内稳定行走
* 防撞 / 急停 / 失控保护

---

### 5️⃣ 应用与产品层

| 角色         | 人数 | 核心职责           |
| ---------- | -- | -------------- |
| 上位机 / 运维平台 | 1  | 地图管理、任务管理、日志回传 |
| 测试 / 现场调试  | 1  | 场景测试、稳定性验证     |

该层在后期投入比例逐渐上升。

---

## 三、人员结构比例（推荐）

以 **10 人团队** 为例：

| 模块          | 占比      |
| ----------- | ------- |
| 定位与感知算法     | **35%** |
| ROS 2 系统与集成 | **25%** |
| 控制与嵌入式      | **20%** |
| 项目管理与架构     | **10%** |
| 测试与产品       | **10%** |

图示理解：

```
算法（定位 / 感知）        ██████████████ 35%
ROS2 系统架构              ██████████ 25%
控制 + 嵌入式              ████████ 20%
架构 / 管理                ████ 10%
测试 / 运维                ████ 10%
```

---

## 四、阶段性投入变化

### 阶段一：0–3 个月（技术验证期）

重点：**能跑起来**

* 算法 / ROS 人员投入最大
* 产品与测试最少

投入比例：

* 算法 + 定位：45%
* ROS 系统：30%
* 控制：15%
* 管理：10%

---

### 阶段二：3–6 个月（系统成型期）

重点：**能稳定作业**

* 系统集成和控制权重上升
* 算法进入优化阶段

投入比例：

* 算法：35%
* ROS + 系统集成：30%
* 控制：20%
* 测试：10%
* 管理：5%

---

### 阶段三：6–12 个月（产品化阶段）

重点：**能长期跑、不出事**

* 测试、部署、运维显著增加
* 算法以稳定性为主

投入比例：

* 算法：25%
* 系统工程：25%
* 控制：20%
* 测试 / 运维：20%
* 管理：10%

---

## 五、关键岗位不可替代性

| 岗位          | 原因           |
| ----------- | ------------ |
| 定位算法负责人     | 决定整套系统是否可用   |
| ROS 2 架构设计者 | 决定系统是否可扩展    |
| 控制工程师       | 决定机器人是否“走得稳” |

这三类岗位不可完全外包。

---

## 六、精简版本（最小可行团队）

若资源受限，可采用 **6 人最小团队**：

| 角色        | 人数 |
| --------- | -- |
| 技术负责人     | 1  |
| ROS2 / 系统 | 2  |
| 定位 / 感知   | 2  |
| 控制 / 嵌入式  | 1  |

该配置可完成：

* 原型验证
* 光伏通道作业
* 基本商业演示

但不适合长期大规模部署。
