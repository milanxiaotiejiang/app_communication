# 风险清单与兜底方案

## 一、总体说明

光伏机器人项目属于**强场景依赖 + 多传感器融合 + 长时间无人运行系统**，风险主要集中在：

* 定位可靠性
* 作业连续性
* 场地一致性不足
* 系统工程复杂度

风险必须做到：

> **可识别、可监控、可退化、可恢复**

而不是“尽量不出问题”。

---

## 二、核心风险总览

| 风险类型    | 风险等级 | 影响范围    |
| ------- | ---- | ------- |
| 定位失效    | 高    | 全系统不可用  |
| SLAM 漂移 | 高    | 作业偏移、碰撞 |
| GNSS 异常 | 高    | 全局规划失效  |
| 场地不一致   | 中    | 局部识别失败  |
| 传感器遮挡   | 中    | 作业中断    |
| 算力不足    | 中    | 实时性下降   |
| 通信异常    | 中    | 状态失控    |
| 软件异常    | 中    | 系统重启    |
| 长时间运行   | 中    | 累积误差    |
| 运维不可控   | 中    | 大规模部署困难 |

---

## 三、详细风险清单与兜底方案

---

## 1️⃣ 定位风险

### 风险 1：局部 SLAM 漂移累积

**表现：**

* 长距离行走后位姿明显偏移
* 实际位置与通道中心不一致
* 进入作业通道失败

**原因：**

* 无图 SLAM 本质为连续位姿估计
* 光伏通道结构高度重复
* 激光特征单一

**兜底方案：**

* 局部 SLAM 仅用于**短距离（几十米）**
* 强制分段：

    * 基站 → 作业入口
    * 作业入口 → 通道内
* 每一段均设置**重定位锚点**

退化策略：

```
连续漂移 → 停车 → 请求 GNSS 修正 → 重置局部坐标系
```

---

### 风险 2：GNSS / RTK 信号异常

**表现：**

* RTK Fix 频繁丢失
* 精度从厘米级退化到亚米级
* 偏移明显但系统无感知

**原因：**

* 光伏板金属反射
* 遮挡天空
* 基站距离过远

**兜底方案：**

* GNSS 仅用于：

    * 全局规划
    * 粗定位
* 禁止直接用于底盘控制

融合策略：

* robot_localization 中设置信任权重
* RTK 非 Fix 状态自动降权
* 只作为慢速修正项

退化模式：

```
RTK 异常 → 自动切换为 LiDAR + Odom + IMU
```

---

### 风险 3：重定位失败

**表现：**

* 系统重启后位置未知
* 无法判断处于第几排

**兜底方案：**

* 引入“结构约束定位”：

    * 光伏排数计数
    * 通道数量计数
* 将“第 N 排、第 M 通道”作为语义位姿

必要时：

* 人工选择作业排号
* 系统自动对齐

---

## 2️⃣ 感知风险

### 风险 4：光伏板高度一致，特征退化

**表现：**

* ICP 不收敛
* 特征点高度重复
* 错误匹配

**兜底方案（明确技术路线）：**

* 不使用点云全局匹配（ICP）
* 不依赖唯一特征点

采用：

* 通道几何模型：

    * 平行边界
    * 固定间距
* 中心线提取
* 宽度约束

本质是：

> 几何约束定位，而非特征定位

---

### 风险 5：杂草、积灰、遮挡

**表现：**

* 激光点云噪声增多
* 边界识别不稳定

**兜底方案：**

* 只使用下半部分点云
* 设置高度过滤
* 引入时间窗口滤波

感知退化策略：

```
边界置信度下降 → 减速 → 保守行驶
```

---

## 3️⃣ 控制与作业风险

### 风险 6：通道内跑偏或剐蹭

**原因：**

* 定位微偏
* 地面不平
* 底盘误差

**兜底方案：**

* 通道内不走“绝对路径”
* 只走“相对中心线”

控制模型：

* 横向误差闭环
* 角度误差闭环
* 低速（< 0.5 m/s）

异常处理：

```
横向误差超阈值 → 急停 → 后退 → 重试
```

---

### 风险 7：作业中断

**表现：**

* 电量不足
* 传感器异常
* 人为干预

**兜底方案：**

* 作业轨迹分段保存
* 每段记录：

    * 排号
    * 通道号
    * 行进方向
    * 完成百分比

重启后：

```
恢复最近一个未完成段
```

---

## 4️⃣ 系统工程风险

### 风险 8：ROS 2 节点异常或崩溃

**兜底方案：**

* 所有核心节点使用：

    * lifecycle node
* 自动状态监测：

    * heartbeat
* 单节点异常不影响全系统

自动恢复：

```
节点 crash → 重启节点 → 重新进入定位态
```

---

### 风险 9：CPU / GPU 算力不足

**表现：**

* 激光延迟
* 控制滞后
* 定位抖动

**兜底方案：**

* 禁止全图优化
* 禁止高频 ICP
* 所有算法可配置频率

设计原则：

> 优先实时性，其次精度

---

## 5️⃣ 长时间运行风险

### 风险 10：累计误差与状态腐化

**表现：**

* 跑一天后定位不可信
* 状态机异常

**兜底方案：**

* 定期软复位：

    * 重置局部 SLAM
    * 保留作业语义进度
* 每完成一排进行一次“逻辑对齐”

---

## 六、风险兜底总体原则

### ✅ 三层兜底模型

```
算法层兜底    → 定位 / 感知退化
系统层兜底    → 节点重启 / 状态回滚
业务层兜底    → 作业段恢复 / 人工接管
```

---

## 七、设计底线原则（非常关键）

1. **不追求全场高精地图**
2. **不追求厘米级长期定位**
3. **允许漂移，但必须可纠正**
4. **允许失败，但必须可恢复**
5. **所有失败必须进入可解释状态**
