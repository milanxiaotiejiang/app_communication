# ✅ 一套完整立项所需文档（给老板 / 投资人 / 管理层）

---

## **1️⃣《项目立项说明书》（最核心）**

> 一页到三页，决定立不立项。

### 必须回答的问题

* 这个项目是干什么的
* 解决什么问题
* 为什么要现在做
* 不做会怎样
* 做成之后能带来什么

### 内容结构（推荐）

**1. 项目背景**

* 原有清洁机器人系统基于 ROS1
* 架构老化，扩展困难
* 新产品方向（光伏清洁 / 室外作业）与原系统场景完全不同
* 需要新一代机器人平台支撑

**2. 项目目标**

* 建设一套可长期演进的 ROS2 机器人平台
* 支持室外大场景
* 支持多形态作业机构
* 支持后续产品快速复用

**3. 项目范围**

* 新平台线（新公司）
* 不继承旧产品技术债
* 保留经验，不继承代码

**4. 阶段成果**

* 3 个月：样机可跑
* 6 个月：稳定作业
* 12 个月：平台化可复用

**5. 风险与应对**

* 场地复杂 → GNSS + 局部SLAM
* 环境重复 → 不依赖全局地图
* 算力受限 → 轻量算法架构

📌 **老板最看重这一份。**

---

## **2️⃣《产品定义文档（PRD Lite）》**

> 不写 UI，不写交互细节，只定义“产品是什么”。

### 内容包括

* 产品类型：光伏清洁机器人平台
* 使用环境：室外、长距离、重复结构
* 工作流程：基站 → 作业 → 回基站
* 作业形式：底盘 + 清洁机构（可带机械臂）
* 使用人群：运维人员

### 明确不做什么

* 不做人形
* 不做复杂自动驾驶
* 不追求厘米级绝对导航

📌 这一份是“技术边界声明”。

---

## **3️⃣《系统总体架构设计文档》**

> 这是你真正的“技术负责人证明”。

内容不用多，但结构一定要清晰。

### 包含：

* 平台分层架构图（你现在这套）
* ROS2 作为中枢
* GNSS / SLAM / EKF 融合思路
* 局部导航 + 作业规划分离

一句话总结：

> 全局粗定位 + 局部高稳定作业。

📌 老板不看代码，只看结构是否清楚、是否靠谱。

---

## **4️⃣《阶段路线图（6–12 个月）》**

非常关键。

### 示例

| 阶段 | 时间     | 目标        |
| -- | ------ | --------- |
| P0 | 0–1 月  | 方案确定、硬件选型 |
| P1 | 2–3 月  | 样机可走、可定位  |
| P2 | 4–6 月  | 可完成完整作业流程 |
| P3 | 7–12 月 | 稳定性、平台化   |

📌 老板最怕“一年之后才能看到东西”。

---

## **5️⃣《人员规划与投入比例》**

不用很细，但必须合理。

例如：

| 角色       | 人数  |
| -------- | --- |
| 系统 / 平台  | 1   |
| 感知 / 定位  | 1–2 |
| 导航 / 控制  | 1   |
| 嵌入式 / 驱动 | 1–2 |
| 产品 / 测试  | 1   |

**初期 5–7 人即可起盘。**

📌 这是立项是否能过的关键。

---

## **6️⃣《风险清单与兜底方案》**

非常加分。

例如：

* RTK 不稳定 → 降级为通道计数
* 地图不可用 → 不依赖地图
* 算法效果不足 → 优先规则稳定性

老板看到“有 Plan B”，心会稳。
