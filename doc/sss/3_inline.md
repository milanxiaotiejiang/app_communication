在 C++ 中，`inline` 的本质是**链接与可见性规则**，而非单纯的“函数一定会被内联展开”。它解决的是**多重定义问题**，性能只是可能的副作用。

---

### 1. `inline` 的真实含义

```cpp
inline int add(int a, int b) {
    return a + b;
}
```

含义是：

* 允许该函数在多个翻译单元中定义
* 链接阶段视为**同一个实体**

是否内联展开，**由编译器自行决定**。

---

### 2. 与宏的本质区别

| 对比项   | `inline` | `#define` |
|-------|----------|-----------|
| 类型检查  | 有        | 无         |
| 作用域   | 有        | 无         |
| 调试支持  | 好        | 差         |
| 编译期行为 | 受编译器控制   | 纯文本替换     |

---

### 3. 典型使用场景

#### 3.1 头文件中定义函数

```cpp
// utils.h
inline int max(int a, int b) {
return a > b ? a : b;
}
```

避免多重定义链接错误。

---

#### 3.2 类内定义的成员函数

```cpp
class A {
public:
    int get() const { return val; }
};
```

类内定义的成员函数**隐式 inline**。

---

#### 3.3 `inline` 变量（C++17）

```cpp
inline int g_val = 10;
```

允许头文件中定义全局变量而不产生 ODR 冲突。

---

### 4. `inline` 与性能

* 可能减少函数调用开销
* 可能增加代码体积
* 编译器会综合判断

**不应为了性能滥用 `inline`**。

---

### 5. `inline` 与 `static` 的区别

| 项目     | `inline` | `static` |
|--------|----------|----------|
| 多文件可见性 | 可以       | 不可以      |
| 实体数量   | 一份       | 每个文件一份   |
| 链接属性   | 外部链接     | 内部链接     |
| 典型用途   | 头文件函数/变量 | 文件私有符号   |

---

### 6. 常见误区

* `inline` ≠ 强制内联
* `inline` 不是优化开关
* 大函数不适合 `inline`
* 递归函数通常无法内联

---

### 一句话总结

> `inline` 解决**定义在哪**的问题，
> 内联展开只是编译器可能采取的优化手段。
