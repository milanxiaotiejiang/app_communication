在 C / C++ 中，`volatile` 用于**告诉编译器：该对象可能在程序控制之外被修改**，因此**禁止对其进行基于“值不变”的优化假设**。

---

### 1. 核心语义

```cpp
volatile int flag;
```

含义只有一条：

> **每一次访问都必须真实地从内存中读取或写入**。

并不保证：

* 原子性
* 线程安全
* 内存可见性顺序

---

### 2. 典型使用场景

#### 2.1 硬件寄存器（嵌入式）

```cpp
volatile uint32_t* UART_DR;
```

寄存器值可能被硬件随时改变。

---

#### 2.2 中断与主程序共享变量

```cpp
volatile bool irq_flag;
```

防止编译器将变量缓存到寄存器中。

---

#### 2.3 自旋等待（仅限非常低级场景）

```cpp
while (!flag) {
}
```

没有 `volatile` 可能被优化为死循环。

---

### 3. `volatile` 不能做什么

✘ 不能保证多线程同步
✘ 不能替代 `mutex / atomic`
✘ 不能防止数据竞争
✘ 不能保证访问顺序

在多线程中，下面是**错误用法**：

```cpp
volatile int cnt; // 仍然存在数据竞争
```

---

### 4. 与 `const` 组合

```cpp
const volatile int status;
```

* 程序不可写
* 硬件或外部仍可改

常见于只读状态寄存器。

---

### 5. C++11 之后的正确替代

* 多线程通信 → `std::atomic`
* 内存顺序控制 → memory order
* 线程同步 → mutex / condition_variable

`volatile` 仍然只适用于：

* 硬件交互
* 中断上下文
* 特殊底层代码

---

### 6. 与 `atomic` 的对比

| 项目      | volatile | atomic |
|---------|----------|--------|
| 防止编译器优化 | ✔        | ✔      |
| 原子性     | ✘        | ✔      |
| 内存序     | ✘        | ✔      |
| 线程安全    | ✘        | ✔      |
| 硬件寄存器   | ✔        | ✘      |

---

### 一句话总结

> `volatile` 解决的是**“编译器是否可以假设值不变”**的问题，
> **不是并发安全工具**。
