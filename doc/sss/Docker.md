Docker 是基于 Linux 内核能力（Namespace、Cgroup、UnionFS）的容器运行与交付平台。

**核心价值**

* 一致的运行环境
* 轻量级隔离
* 快速交付与部署

* Docker 负责**单机容器运行**
* Kubernetes 负责**集群编排**
* K8s 不依赖 Docker，只依赖 OCI

> Docker 本质是基于 Linux 内核能力构建的轻量级进程隔离与交付机制，而不是虚拟化技术。

**Namespace 是 Linux 内核提供的资源视图隔离机制**，用于让进程“认为自己运行在一个独立系统中”。

> **同一份内核，不同的资源视图**

* 进程之间互相不可见
* 容器拥有“独立系统视角”
* 不做资源限制，只做隔离

| Namespace | 隔离对象       | 关键作用             |
| --------- | ---------- | ---------------- |
| **PID**   | 进程号        | 容器内 PID 从 1 开始   |
| **NET**   | 网络栈        | 独立 IP / 路由 / 端口  |
| **MNT**   | 挂载点        | 容器文件系统视图         |
| **UTS**   | 主机名        | hostname 隔离      |
| **IPC**   | 共享内存 / 信号量 | 进程通信隔离           |
| **USER**  | UID / GID  | 非 root 映射成宿主普通用户 |

> Namespace 是 Linux 提供的资源视图隔离机制，使进程在同一内核上拥有彼此隔离的系统视角，是容器“看起来像一台独立机器”的基础。

**Cgroup（Control Groups）是 Linux 内核的资源限制与统计机制**。

> **对进程组进行资源配额、限制和监控**

* 防止进程抢占系统资源
* 对容器进行资源限制
* 提供资源使用统计

| 资源       | 控制内容            |
| -------- | --------------- |
| CPU      | 使用比例、调度权重       |
| Memory   | 内存上限、OOM 行为     |
| Block IO | 磁盘 IO 限速        |
| PIDs     | 最大进程数           |
| Network  | 间接控制（tc / eBPF） |

* 基于虚拟文件系统
* `/sys/fs/cgroup`

核心操作：

* 创建 cgroup 目录
* 写入限制参数
* 将进程 PID 写入 `cgroup.procs`

👉 **Cgroup 是内核级“资源调度策略”**

> Cgroup 是 Linux 内核提供的进程资源控制机制，用于对 CPU、内存等资源进行限制、分配和统计，是容器“不会把宿主机拖垮”的核心保障。

> 容器本质上是 **Namespace 提供“独立视角”，Cgroup 提供“资源边界”，再加上文件系统隔离后形成的受控进程集合**。


## 一、容器为什么比虚拟机快

**核心原因：没有硬件虚拟化层**

### 本质差异

* **虚拟机**：
  应用 → Guest OS → Hypervisor → Host OS → 硬件
* **容器**：
  应用 → Host OS → 硬件

容器：

* 不启动独立内核
* 不模拟硬件
* 本质是宿主机上的普通进程

### 直接结果

* 启动速度：秒级 vs 分钟级
* 内存占用：MB 级 vs GB 级
* 系统调用：无虚拟化陷阱

**面试一句话**

> 容器比虚拟机快，是因为容器不做硬件虚拟化，而是直接复用宿主机内核，本质上只是受限进程。

## 二、Namespace 和 Cgroup 的作用

### Namespace ——「隔离」

解决“**看不见**”的问题

* 进程看不到别的进程
* 网络、文件系统、主机名独立
* 不限制资源使用量

### Cgroup ——「限制」

解决“**用多少**”的问题

* CPU 配额
* 内存上限
* IO 限速
* 进程数限制

**组合后的容器本质**

> Namespace 提供隔离视图，Cgroup 提供资源边界。

## 三、镜像为什么分层

### 分层的核心目的

#### 1️⃣ 复用

* 多个镜像共享基础层
* 节省磁盘空间

#### 2️⃣ 增量构建

* 只重建变化的层
* 加快构建速度

#### 3️⃣ 增量分发

* 只拉取缺失层
* 提升镜像分发效率

---

### 容器如何写数据

* 镜像层：只读
* 容器启动时：
  ➜ 增加一个 **可写层（Copy-on-Write）**

**面试一句话**

> 镜像分层是为了实现最大化复用和增量构建，本质是 UnionFS 的写时复制机制。

---

## 四、容器如何实现网络隔离

### 核心机制：Network Namespace

每个容器拥有：

* 独立网络协议栈
* 独立 IP、端口、路由表

---

### 默认 bridge 网络原理

```
容器 eth0
  ↕ veth pair
docker0 网桥
  ↕
宿主机网卡
```

* veth：虚拟网线
* docker0：二层交换机
* iptables：转发与 NAT

---

### 网络隔离本质

* Namespace 隔离网络视图
* iptables 控制访问路径

---

## 五、Docker 如何限制内存

### 核心机制：Cgroup Memory Controller

限制方式：

* 设置内存上限
* 控制 OOM 行为

关键参数：

* `memory.max`
* `memory.swap.max`
* `oom_score_adj`

---

### 超限会发生什么

* 达到上限
* 内核触发 OOM
* 容器内进程被杀死
* 容器退出

**面试一句话**

> Docker 通过 Cgroup 的内存子系统对容器进行硬限制，防止单个容器耗尽宿主机内存。

---

## 六、容器重启 vs 进程重启的区别

### 进程重启

* 容器内某个进程异常
* PID 变化
* 容器仍然存在

### 容器重启

* 容器被销毁后重新创建
* 可写层重置
* 网络、PID 重新分配

---

### Kubernetes 视角

* 进程挂 → kubelet 重启容器
* 容器挂 → Controller 重建 Pod

**关键认知**

> 容器不是进程管理器，容器生命周期高于进程。

## 七、Docker 的安全问题有哪些（高频）

### 1️⃣ 内核共享风险（根本问题）

* 所有容器共享宿主机内核
* 内核漏洞 = 全容器风险

---

### 2️⃣ 特权容器

* `--privileged`
* 可访问宿主设备
* 极易逃逸

---

### 3️⃣ USER Namespace 未启用

* 容器 root = 宿主 root
* 一旦逃逸，后果严重

---

### 4️⃣ 不安全的 Volume 挂载

* 挂载 `/`、`/var/run/docker.sock`
* 容器可控制宿主 Docker

---

### 5️⃣ 镜像安全

* 恶意镜像
* 含漏洞依赖
* root 用户运行

---

### 6️⃣ 网络与能力问题

* 未限制 Linux Capabilities
* 网络策略缺失

---

**安全加分回答**

> 容器的安全边界弱于虚拟机，因此生产环境必须通过最小权限、非 root、Cgroup、Capability 收缩等方式进行防御。

---

## 总结一句话（整组升维）

> Docker 通过 Namespace 实现隔离、通过 Cgroup 实现资源控制、通过分层文件系统实现高效交付，本质上是一种受控的进程运行模型，而不是虚拟化技术。
