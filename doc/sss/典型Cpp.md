## 1️⃣ 左值 / 右值 / xvalue 与 `std::move`

如何通过引用折叠规则区分 T&、T&& 在模板中的真实类型？std::move 本质上做了什么？

**左值（lvalue）**
具有稳定身份与可寻址性的表达式，通常对应一个具名对象，生命周期可控。

**纯右值（prvalue）**
不具备可寻址身份的临时值，通常用于初始化或计算结果。

**将亡值（xvalue）**
仍具身份，但其资源即将被复用的值，典型来源是 `std::move` 的结果。

**`std::move` 的本质**
并不移动任何资源，仅做一次 **`static_cast<T&&>`**，将表达式显式转换为 **xvalue**，从而允许后续触发移动构造或移动赋值。

**引用折叠规则**

* `T& & → T&`
* `T& && → T&`
* `T&& & → T&`
* `T&& && → T&&`

**完美转发**
在模板中通过 `T&&` + `std::forward<T>`，保持实参原有的值类别。

## 2️⃣ 拷贝构造、移动构造与拷贝省略

在哪些场景下一定会触发拷贝省略？关闭拷贝省略后，对对象生命周期与性能有什么影响？

**拷贝构造**
通过已有对象构造新对象，语义是“复制资源”，是否深拷贝由类型语义决定。

**移动构造**
通过“接管”源对象资源完成构造，源对象进入**有效但未指定状态**。

**拷贝省略（RVO / NRVO）**

* 返回局部对象时，编译器可直接在调用方栈帧中构造对象
* C++17 起，某些场景下 **拷贝省略是强制的**

**关闭拷贝省略后**

* 返回值需要经历移动构造（或拷贝构造）
* 对象生命周期更长，性能与可观察行为均可能变化

## 3️⃣ RAII 与异常安全保证

如何设计一个资源管理类同时满足 基本保证、强保证 与 不抛异常保证？常见破坏异常安全的代码模式有哪些？

**RAII**
资源的获取与释放绑定于对象生命周期，构造时获取，析构时释放。

**异常安全的三种保证**

1. **基本保证**：异常发生时，对象仍处于有效状态，无资源泄漏
2. **强保证**：操作要么成功完成，要么对象状态不发生变化
3. **不抛异常保证**：操作保证不抛出异常（如析构函数）

**工程要点**

* 析构函数禁止抛异常
* 使用值语义与临时对象实现提交 / 回滚
* `unique_ptr`、`lock_guard` 是典型 RAII 工具

## 4️⃣ `shared_ptr` / `unique_ptr` / `weak_ptr`

引用计数如何实现？为什么 weak_ptr 不会增加引用计数？如何解决循环引用问题？

**`unique_ptr`**

* 独占式所有权
* 禁止拷贝，支持移动
* 零额外开销，最推荐的默认选择

**`shared_ptr`**

* 引用计数式共享所有权
* 控制块中包含引用计数（通常是原子操作）
* 拷贝 +1，析构 −1，归零时释放资源

**`weak_ptr`**

* 不参与资源所有权
* 仅观察控制块状态
* `lock()` 可安全尝试提升为 `shared_ptr`

**循环引用问题**

* `shared_ptr` 环会导致引用计数永不归零
* 通过将“非拥有关系”改为 `weak_ptr` 解决

## 5️⃣ C++ 内存模型与 `std::atomic`

memory_order_relaxed / acquire / release / seq_cst 的语义差异是什么？哪些场景可以安全使用 relaxed？

**`memory_order_relaxed`**

* 仅保证原子性
* 不提供顺序与可见性保证
* 适用于统计计数、监控指标

**`release / acquire`**

* `release`：之前的写对后续 `acquire` 可见
* 构成 **happens-before** 关系
* 常用于发布-订阅模型

**`seq_cst`**

* 最强顺序一致性
* 全局单一修改序列
* 最安全但代价最高

## 6️⃣ 锁与同步原语选型

mutex、recursive_mutex、shared_mutex、自旋锁的适用场景分别是什么？在高并发读场景下如何选型？

* `mutex`：通用互斥，最常用
* `recursive_mutex`：同一线程可重复加锁（应谨慎使用）
* `shared_mutex`：读写锁，读多写少场景
* 自旋锁：临界区极短、不可睡眠、避免线程切换

**高并发读场景**

* 写少读多 → `shared_mutex`
* 极短临界区 → 自旋锁
* 普通场景 → `mutex`

## 7️⃣ 条件变量与虚假唤醒

为什么 condition_variable::wait 必须配合谓词使用？虚假唤醒产生的根本原因是什么？

**正确用法**

```cpp
cv.wait(lock, predicate);
```

**原因**

* 条件变量允许 **虚假唤醒**
* 唤醒不等于条件满足
* 唤醒与条件状态并非原子操作

**根本原因**

* 为适配多平台实现
* 避免内核级严格保证带来的性能成本

## 8️⃣ 虚函数、虚表与析构设计

为什么基类析构函数通常要声明为 virtual？纯虚析构函数是否合法？虚函数调用在构造与析构阶段的行为如何？

**虚函数机制**

* 含虚函数的类通常拥有虚表指针
* 调用时通过对象实际类型进行动态分派

**析构函数为何应为 `virtual`**

* 通过基类指针删除派生类对象时，保证完整析构

**纯虚析构函数**

* **合法**
* 仍需提供函数定义
* 用于强制类不可实例化

**构造 / 析构阶段**

* 构造中虚调用不具备多态性
* 析构中自下而上执行

## 9️⃣ 模板、特化与编译期分发

模板特化、偏特化与 constexpr if 的区别与使用边界是什么？如何在编译期完成类型分发而避免运行时开销？

**全特化**

* 针对某一具体类型提供完全替代实现

**偏特化**

* 针对一类类型模式（如指针、容器）

**`constexpr if`**

* 编译期条件分支
* 未选中分支不会实例化

**编译期类型分发**

* `if constexpr`
* traits + 模板特化
* 避免 `virtual` / `if` 带来的运行期开销

## 🔟 C++ 性能分析方法论

如何定位一个 C++ 服务中的性能瓶颈？从编译期（如 ODR、内联、优化级别）到运行期（CPU cache、内存分配、锁竞争）应如何系统性分析？

**系统性步骤**

1. 先定位：CPU / 内存 / I/O / 锁
2. 使用 profiler（perf、vtune、gprof）
3. 分析热点函数与调用路径
4. 关注：

    * cache miss
    * 内存分配频率
    * 锁竞争
    * 不必要的拷贝

**原则**

* 不凭直觉优化
* 数据驱动决策
* 优化前后必须可量化验证
