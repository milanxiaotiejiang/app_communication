## 一、进程 / 线程 / 调度（必问）

### **1️⃣ Linux 中进程和线程的本质区别是什么？**

**追问：**

* Linux 内核里有没有“真正的线程”？
* `clone()` 和 `fork()` 的区别？
* 为什么说 Linux 是“轻量级进程（LWP）模型”？
* 线程崩溃一定会导致进程退出吗？什么情况下不会？

进程管资源,线程管执行,
Linux 内核中没有独立于进程的线程概念，只有 task_struct，线程在内核看来就是一种共享资源的进程。
fork 创建一个几乎完全独立的进程；
clone 允许有选择地共享资源，用于实现线程。
因为 Linux 用统一的进程模型实现线程，线程只是共享资源更多的进程，因此称为轻量级进程（LWP）。
是否导致进程退出，取决于线程是“正常结束”还是“触发进程级致命信号”。

## 二、内存管理（高频 + 难度分水岭）

### **2️⃣ 虚拟内存的作用是什么？Linux 是如何实现的？**

**追问：**

* 虚拟地址到物理地址的完整过程？
* 页表是每个进程一份吗？
* 多级页表为什么能省内存？
* `mmap` 和 `brk` 的区别？glibc malloc 用哪个？
* Page Cache 属于用户态还是内核态内存？

虚拟内存是 Linux 内核通过多级页表管理的、为每个进程提供独立连续地址空间的机制，支持隔离、共享、按需加载和高效缓存。

## 三、malloc / free（C++ 岗必问）

### **3️⃣ malloc 一块内存后，Linux 内部发生了什么？**

**追问：**

* malloc 一定会触发系统调用吗？
* 小对象和大对象分配路径一样吗？
* 内存碎片有哪些类型？如何缓解？
* free 之后内存立刻还给 OS 吗？
* 为什么 `top` 看到内存不降？

malloc 本质是用户态内存池分配，小对象复用池内存，大对象 mmap 申请内核内存，free 并不一定立刻释放给 OS，碎片由分配器和内核管理缓解。

## 四、文件系统（非常爱问）

### **4️⃣ Linux 文件系统是如何组织和查找文件的？**

**追问：**

* inode 里有什么？没有什么？
* 一个文件名很长会不会影响读取性能？
* 硬链接 vs 软链接的本质区别？
* 删除一个正在被使用的文件会发生什么？
* ext4 为什么比 ext3 快？

Linux 文件系统通过 inode + 目录组织文件，目录保存文件名映射，inode 保存元信息和数据块指针；硬链接共享 inode，软链接保存路径；删除文件只删除目录项，inode 还在；ext4 通过延迟分配、多块分配和 extents 提升性能。

## 五、I/O 模型（中高级分水岭）

### **5️⃣ Linux 的五种 I/O 模型分别是什么？**

**追问：**

* 阻塞 vs 非阻塞的本质差异？
* `select / poll / epoll` 的核心区别？
* epoll 为什么快？真的 O(1) 吗？
* LT 和 ET 的区别？ET 为什么容易丢事件？
* epoll 能监听普通文件吗？为什么？

Linux 五种 I/O 模型：阻塞、非阻塞、多路复用、信号驱动、异步 I/O；阻塞等待内核完成，非阻塞立即返回；select/poll 遍历 fd，epoll 内核维护就绪链表，LT 持续通知，ET 只触发一次；普通文件 I/O 永远就绪，ET 不适用。

## 六、进程间通信（IPC）

### **6️⃣ Linux 常见 IPC 方式有哪些？各自适用场景？**

**追问：**

* 管道为什么只能半双工？
* 共享内存为什么最快？快在哪里？
* shm 一定比 socket 快吗？
* 为什么高性能服务更偏向 socket 而不是 shm？
* fork 后父子进程如何共享数据？

Linux IPC 方式多样：管道、消息队列、信号、共享内存、套接字；共享内存最快因为无需内核拷贝，socket 可扩展跨主机；管道半双工，fork 后父子通过 COW 共享，想共享大量数据用 shm 或 mmap。

## 七、信号（很多人答得很虚）

### **7️⃣ Linux 信号的本质是什么？**

**追问：**

* 信号是如何从内核送到进程的？
* 哪些信号不能被捕获？为什么？
* 信号和中断的区别？
* 在信号处理函数里能做哪些事？哪些是危险的？
* `SIGCHLD` 的作用？

Linux 信号是内核向进程发送的异步事件通知，SIGKILL 和 SIGSTOP 无法捕获；信号在用户态通过位图和处理函数传递；安全操作需 async-signal-safe；SIGCHLD 用于子进程退出通知父进程。

## 八、CPU & 调度（偏系统）

### **8️⃣ Linux 进程调度是如何做的？**

**追问：**

* CFS 的核心思想是什么？
* vruntime 是什么？
* nice 值是如何影响调度的？
* 实时进程一定比普通进程先执行吗？
* 多核下进程如何负载均衡？

Linux 进程调度通过 CFS 和实时策略分配 CPU，CFS 用 vruntime 保证公平，nice 值影响虚拟运行时间，实时进程优先，负载均衡保证多核 CPU 上进程均匀分布。

## 九、性能调优（面试加分题）

### **9️⃣ Linux 下你如何定位一个“CPU 飙高 / 内存泄漏 / I/O 卡顿”的问题？**

**追问：**

* CPU 高但 load 不高说明什么？
* load 高但 CPU 不高说明什么？
* 如何判断是用户态慢还是内核态慢？
* 如何确认是 Page Cache 还是程序真的占内存？
* 线上能用 gdb 吗？替代方案？

定位性能问题先分析 CPU、内存、I/O，CPU 高用 perf/top 查用户态热点，load 高低区分 I/O 等待，区分用户态/内核态，Page Cache 可回收不算程序占用，线上用 gdb 替代工具如 perf/strace/eBPF。

## 十、系统稳定性（架构视角）

### **🔟 一个 Linux 服务“频繁 OOM”，你会怎么分析？**

**追问：**

* OOM killer 杀进程的依据？
* RSS / VSZ / PSS 区别？
* cgroup 在 OOM 中的作用？
* 为什么容器里更容易 OOM？
* 如何限制进程最大内存？

服务频繁 OOM 先看 OOM killer 日志，分析 RSS/VSZ/PSS，排查内存泄漏，容器受 cgroup 限制更易 OOM，可用 ulimit/cgroup/docker 限制内存上限。
